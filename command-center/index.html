Operating principle

Make every change inspectable before it becomes operational.
ObserveDraftValidateActivate

Historical evidence stays immutable. Production changes require an explicit operator action and leave a revisioned audit trail.

Release path

One foundation, two deliberate releases.

v0.4 establishes the investigation and configuration surfaces. v0.5 builds the experiment and promotion workflow on top of those versioned controls.

Control boundary

A configuration UI is an operational control plane.

The Command Center will treat policy writes differently from ordinary alert review. Convenience does not erase the need for authorization, provenance, or recovery.

01Off by default

Configuration mutation requires an explicit deployment setting and a dedicated write scope.

02Preview before activation

The operator sees validation results, exact changes, affected historical alerts, and broad-match warnings.

03Future events only

New policy or asset definitions do not rewrite old verdicts or their captured asset snapshots.

04No container control

The dashboard does not receive a Docker socket or permission to restart the ingest pipeline.

v0.5 workflow

Lab work cannot silently become production behavior.

  1. 01
    Create a candidate

    Fork the active production revision into an isolated draft.

  2. 02
    Run the evaluation

    Replay a controlled dataset without touching live checkpoints or verdicts.

  3. 03
    Review the delta

    Inspect changed decisions, regressions, coverage, latency, and integrity results.

  4. 04
    Promote or reject

    Explicitly activate the candidate or leave production unchanged.
